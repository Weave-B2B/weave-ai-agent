# 공통 스키마 검증 기준

`schemas.py`의 현재 검증 기준은 [runtime-manifest.json](runtime-manifest.json)이다. 파일의 SHA-256과 `SCHEMA_VERSION`을 고정 값과 비교하므로, 기록되지 않은 스키마 변경은 계속 테스트에서 실패한다. 실행 중 계산한 해시로 기대값을 자동 갱신하지 않는다.

[초기 데이터셋 manifest](../eval/dataset/manifest.json)는 데이터셋 작성 당시의 스키마 지문을 담는다. 현재 런타임과 구분하여 원본을 보존한다. 런타임 manifest의 `dataset_baseline`이 이 기록을 참조하고, `changes_since_dataset_baseline`은 이후 `dev`에 병합된 스키마 변경의 커밋과 내용을 기록한다.

2026-11-20 기준 런타임 버전 문자열은 기존 코드와 같은 `0.3.0`이다. 버전 문자열만으로 변경 여부를 판단하지 않으며 파일 지문도 함께 검사한다. 이 기록 추가는 새 스키마 변경이나 버전 정책 확정이 아니다. 특히 산정 intent 변경은 동작에 영향을 주므로 모든 변경이 호환된다고 가정하지 않는다.

향후 공통 스키마를 변경할 때는 다음을 함께 검토한다.

1. 입력·출력·intent 및 관련 에이전트에 미치는 영향과 스키마 버전 정책을 확인한다.
2. 변경 절차(공통기준 13장)에 따라 검토한 변경만 런타임 manifest의 지문·버전·변경 이력에 반영한다. 초기 데이터셋 지문을 현재 값으로 덮어쓰지 않는다.
3. `python -m pytest tests/test_dataset_integrity.py -q`와 해당 에이전트의 계약 테스트를 실행한다. 데이터셋 전체 레코드의 파싱 통과는 형식 호환 확인이며 모델 성능이나 전체 동작 호환의 보증은 아니다.
