# 평가·검수 기준

## 검사 층

| 층 | 확인 |
|---|---|
| 구조·연결 | 제공 Pydantic 스키마, 고유 ID, 같은 context, 전체 upstream·PM 참조 |
| 출처 | PD 원문 불변, Unicode span, 기준선 문서, 문서버전/섹션/페이지/줄·quote |
| 계산 | 팀원 임의 MD/lines 보존, calc_cost 재계산 일치, 합계/초안 금액 |
| 상태 | 적절한 blocking 대기·기술 실패·게이트 차단·미해결 follow-up 보존 |
| 의미·실무 | 항목 누락/허위추가, 선택/수량/부정 조건, 조항의 실제 지지, 작업/MD 가정의 현실성 — 사람 검수 |

자동 검증 PASS는 위 앞부분의 데이터 무결성이다. 실제 에이전트 성능·도구 실패 재현·프롬프트 인젝션 방어 성공을 측정한 것이 아니다. noisy expected_output도 사람이 검수하기 전 초안이다.

## 지표

- A1: 의미 항목 F1, intent·조건 보존, span 정확성. 동등한 분할/표현은 의미 매핑 후 평가한다.
- A2: 매칭된 항목의 accuracy/macro-F1·unclear precision/recall, 검색 Hit@k/MRR, 인용 존재와 결론 지지율 분리.
- A3: 산정 대상·작업 누락/중복·not_estimable, 금액 계산 재현, 초안 출처/금액 복사. **MD MAPE/정확도는 검수 전 기본 비활성**이다. 가상 MD를 맞추는 것이 실제 추정 능력은 아니다.
- 통합: 정상·보류·기술 실패를 포함한 기대 상태 도달률과 ready 완료율을 별도 보고한다. 미검토 A3 호출·타 프로젝트 인용·승인 변경 중복 산정은 0건을 제안한다.

정확 일치: ID의 관계(예시 문자열 자체는 런타임 발급값으로 매핑), 수치/단위, 원문 부분 문자열, 문서 버전, 게이트, 산식. 의미 동등 허용: 설명·질문 문구·동등 항목화·충분한 대체 근거. 사람 검수: 사실 지지·계약 해석·작업량·실제 공수·PM 권한.

## 제공 스키마의 한계

schema/schemas.py는 받은 파일을 그대로 유지했다. version 문자열·빈 quote·verified 여부·ID 집합·원문 일치·동일 프로젝트를 모두 자동 강제하지는 않는다. tools/validate.py가 데이터 수준에서 추가 검증한다. 운영 인증/권한·검토 원본성·도구 출처는 호출부가 별도로 보장해야 한다.

`totals_source=calc_cost` 문자열만으로 실제 호출을 증명하지 못한다. 실제 평가에는 result_id, tool, 입력/출력 해시·버전·시각·성공 여부를 trace로 남긴다. 현재 데이터 검증 중 calc_cost를 호출한 것은 기대 금액 재계산이지 실제 에이전트의 도구 사용 증거가 아니다.

## 검수 절차

1. 대표 정상 A001, 일정 충돌 A004, 사실 부족 A005, mixed B003/C006을 세 사람이 공동 검토.
2. A1 항목·조건, A2 근거 지지, A3 작업/가정은 담당 외 한 명이 교차 검토.
3. 검수자·날짜·변경 사유를 기록한 뒤 승인 상태를 별도 승격. 현재 승인 레코드는 만들지 않았다.
4. 수정 시 linked fixture·PM target·chain·split·모아보기·정답을 함께 갱신.
5. validation은 개발용으로 보고, 실제 blind 성능은 새 미노출 사례로 평가.
