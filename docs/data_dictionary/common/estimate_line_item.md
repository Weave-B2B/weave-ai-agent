## 개요

작업 하나가 여러 요청 항목을 지원할 때 필요한 선택적 연결 테이블 제안이다. 첫 단일 항목 연동의 선행 조건은 아니다. 공통 Line.item_ids는 배열이지만 기존 estimate_line.request_item_id는 단일 값이므로 확장 시 관계를 명확히 해야 한다.

현재 에이전트 3 연계에서 확인한 컬럼을 정리했다. 이 폴더의 분류는 전용 소유권을 뜻하지 않으며, 기존 ERD 전체 DDL 명세도 아니다.

**값 예시 안내:** UUID·시각·해시는 문서용 가상 값이다. 같은 의미의 참조 ID는 다른 문서에서도 동일하게 썼다. 각 행은 값의 형태를 설명하며 전체 INSERT 또는 실제 승인 기록이 아니다. 상태 코드가 확인되지 않은 곳은 미정으로 남겼다. [예시 ID 설명](../example_values.md) 참조.

## 추가 제안 컬럼

**아래 이름·타입·키·NULL 정책은 모두 제안이며 CN 합의·DB 구현 완료를 뜻하지 않는다.**

| 컬럼 | 타입 | 키 | NULL 허용 | 정의 | 값 예시 | 활용·작성 방식 |
|---|---|---|---|---|---|---|
| estimate_line_id | UUID | 복합 PK + FK → estimate_line | 아니오(제안) | 공유 작업 행 | `655a2c8f-14e4-50c3-b5c1-b6b78dcbd9e7` | 동일 작업 행을 한 번만 산정 |
| request_item_id | UUID | 복합 PK + FK → request_item | 아니오(제안) | 관련 요청 항목 | `e19e8619-b02e-5636-affb-2e433a2299d7` | 동일 행-항목 조합 중복 금지 |

## 저장·갱신 규칙과 협의 사항

- PK 후보는 (estimate_line_id, request_item_id)다. 같은 검토 버전의 항목끼리만 연결되도록 검사한다.
- 채택 시 기존 estimate_line.request_item_id의 단일 소유 관계를 어떻게 바꿀지 함께 결정한다. nullable로 바꾸고 연결 테이블을 기준으로 삼을지, 대표 항목을 남길지 미확정이다.
- 단일 필수 FK를 그대로 둔 채 조인 테이블만 더하면 대표 항목/전체 항목 관계가 모호해진다. 관계 변경 없이 공유 작업 지원이 끝났다고 표시하지 않는다.
- 전체 합계는 estimate_line_id를 기준으로 한 번만 계산한다. 조인 후 항목 수만큼 MD·금액을 중복 합산하지 않는다. 항목별 금액 배분 기준은 별도 설계다.
