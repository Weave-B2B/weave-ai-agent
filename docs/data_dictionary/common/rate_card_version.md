## 개요

프로젝트에 적용할 단가표의 버전·통화·적용일·MD당 시간을 정의하는 기존 테이블이다. MVP는 고정된 합성 단가를 사용한다. 기존 단가표 API A-30~33의 상세 계약과 실제 구현은 별도 확인한다.

현재 에이전트 3 연계에서 확인한 컬럼을 정리했다. 이 폴더의 분류는 전용 소유권을 뜻하지 않으며, 기존 ERD 전체 DDL 명세도 아니다.

**값 예시 안내:** UUID·시각·해시는 문서용 가상 값이다. 같은 의미의 참조 ID는 다른 문서에서도 동일하게 썼다. 각 행은 값의 형태를 설명하며 전체 INSERT 또는 실제 승인 기록이 아니다. 상태 코드가 확인되지 않은 곳은 미정으로 남겼다. [예시 ID 설명](../example_values.md) 참조.

## 기존 ERD에서 활용하는 컬럼

**ERDCloud v0.6에서 내보낸 PostgreSQL SQL과 대조했다.** 타입·NULL·PK/FK는 내보내기 정의 기준이며 실제 DB 적용 검증은 아니다. 기본값은 원본에 없으면 임의 지정하지 않는다. UQ·CHECK 주석은 실행 제약과 구분한다.

| 컬럼 | 타입 | 키 | NULL 허용 | 정의 | 값 예시 | 활용·작성 방식 |
|---|---|---|---|---|---|---|
| rate_card_version_id | UUID | PK | 아니오 | 단가표 버전 ID | `cd57ac4d-6b6c-5cfc-b1cf-3082d30992c6` | Agent3Input.rate_card_id와 매핑 |
| project_id | UUID | FK → project | 아니오 | 대상 프로젝트 | `ca3df8e9-f107-5e5a-a1da-789f0baccdec` | 적용 범위 확인 |
| rate_card_version_no | INTEGER | — | 아니오 | 프로젝트 내 단가표 순번 | 1 | UQ 범위는 실제 DDL 확인 |
| hours_per_md | NUMERIC(10, 2) | — | 아니오 | 1MD에 대응하는 시간 | `8.0` | 8시간을 임의 확정하지 않음; 값 8.0은 형식 설명용 가정이며 실제 환산 기준은 미확정 |
| rate_currency | VARCHAR(3) | — | 아니오 | 통화 | KRW | 현재 calc_cost의 통화 |
| rate_effective_date | DATE | — | 아니오 | 적용 시작일 | 2026-10-01 | 기준 시점과 적용 정책 확인 |
| created_at | TIMESTAMPTZ | — | 아니오 | 버전 생성 시각 | `2026-10-28T10:00:00+09:00` | 추적용 |
| created_by | UUID | FK 주석 → company_member (제약문 없음) | 아니오 | 등록자 | `4e74e319-db07-5c8e-8ff4-84a8964e9db1` | 기존 권한 기준 활용 |

## 추가 제안 컬럼

**아래 이름·타입·키·NULL 정책은 모두 제안이며 CN 합의·DB 구현 완료를 뜻하지 않는다.**

| 컬럼 | 타입 | 키 | NULL 허용 | 정의 | 값 예시 | 활용·작성 방식 |
|---|---|---|---|---|---|---|
| rate_unit | VARCHAR(10) | — | 아니오(제안) | 단가의 분모 단위 | `MD` | 표 안에서 단위가 섞이면 role_rate 쪽에 배치 |

## 저장·갱신 규칙과 협의 사항

- 기존 원가·판매 단가가 시간당인지 MD당인지 단위 계약이 필요하다. hours_per_md가 있다는 사실만으로 단가 단위를 단정하지 않는다.
- 현재 코드·합성 파일은 KRW/MD만 계산하며 HOUR 단가 자동 환산은 구현하지 않았다. HOUR 지원 시 환산·반올림 계약을 먼저 정한다.
- 새 단가표가 등록됐다는 이유만으로 과거 승인 계산을 자동 무효화하지 않는 방향이다. 반면 현재 로컬 코드는 같은 단가 ID의 파일 내용이 바뀌면 승인을 거부한다. 운영은 불변 버전·당시 snapshot으로 이 차이를 해소해야 한다.
- 현재 로컬 파일의 `synthetic`, `unit`, `vat_included`도 계산 출처에 보존한다. DB 정형 컬럼 추가 여부는 미확정이며 이번 v0.7의 추가 컬럼으로 확정하지 않는다.
