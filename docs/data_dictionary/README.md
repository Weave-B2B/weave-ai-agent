# 데이터 딕셔너리

문서 v0.3 · 2026-10-28 · 케클업 / Weave

DB 테이블의 컬럼·타입·키·NULL 허용·정의·예시·사용 규칙을 정리한다. 테이블 정의는 업무 영역과 공통 사용 범위에 따라 한 곳에서 관리하고, 에이전트별 문서는 필요한 테이블을 링크로 참조한다.

```text
docs/data_dictionary/
├── README.md
├── common/          # 공통 분석·버전·단가·산정·협의안·질문·실행 기록
├── requests/        # 변경 요청·요청 항목·범위 PM 판단
├── agent3/          # 산정 승인 제안·실행 대응·JSON 설명
├── references/      # ERD 원본 SQL·출처·판독 정정
└── example_values.md
```

| 공통 예시·출처 | [예시 값](./example_values.md), [references](./references/README.md) | 가상 ID·ERDCloud v0.6 SQL·판독 정정 |

총 15개 테이블/후보 구조의 설명을 유지했다. 이 분류는 문서 배치 기준이지 팀별 DB 소유권이나 신규 테이블 채택을 확정한 것이 아니다. 현재 내용은 에이전트 3 연계에서 확인한 범위이며 팀 전체 테이블을 모두 문서화한 것은 아니다.

## 읽는 법

- **기존 구조:** ERDCloud v0.6 내보내기 SQL과 대조했다. 실제 운영 DB 적용 검증과는 다르다.
- **추가 제안:** 신규 컬럼·테이블·키·NULL 정책은 CN 채택 전이다. 공통 구조는 기존 저장소로 대체할 수 있다.
- **주석 제약:** UQ/CHECK/FK가 SQL 주석에만 있는 경우 실제 제약 생성문과 구분한다.
- **가상 예시:** UUID·시각·해시·합성 단가는 실제 고객 데이터나 승인 증빙이 아니다. 키와 NULL 허용 여부는 별개다.

ERD 수정·추가 초안 v0.7은 변경 대상을 협의하는 문서이고, 이 딕셔너리는 데이터를 사용하는 방식을 설명한다. v0.7은 그대로 보존했다. 이번 작업은 문서 이동·색인·상대 링크 정리이며 commit·push·PR·migration 실행은 하지 않았다.
