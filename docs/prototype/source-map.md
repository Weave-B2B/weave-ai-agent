# AI 확인용 화면 — 기획·설계 근거

확인일: 2026-10-28 (Asia/Seoul) · 조사 담당: `dev-team-research`.

현재 요청은 **AI 서버 저장소에서 Figma 형태의 변경요청 화면으로 에이전트 동작을 확인**하는 것이다. 아래 문서는 기존 제품 기획의 근거이며, 전체 서비스·업무 백엔드·DB·인프라를 이번 작업에 모두 구현하라는 범위가 아니다. 화면·연결 수준은 기획 검토 후 사용자와 확정한다.

## 조사 결론

PRD와 기능요구사항이 이미 있어 기획을 처음부터 다시 작성할 필요는 없다. 다만 PRD는 MVP 제안, 요구사항은 우선순위 제안안이며 최종 승인본으로 확인되지 않았다. 이번 로컬 UI의 화면 범위·mock/기존 API 연결·미지원 상태를 별도의 수용 기준으로 보충하면 된다.

노션의 `05. PRD v0.1`과 `05-2. MVP 기능 요구사항 v0.2`를 실제 조회했다. 팀 페이지 안에서 `PRD`, `MVP v2.0`을 추가 검색했지만 이 조사에서 더 최신의 확정 PRD를 특정하지는 못했다. 마지막 편집 시각만으로 문서의 업무상 우선순위를 정하지 않았다.

## 현재 구현과 구분할 부분

현재 API와 동작은 [Agent 3 초기 MVP 설명](../agent3/agent3-mvp.md)을 확인했다. 이 문서는 PRD 전체 구현 완료의 증거가 아니라 현재 로컬 연결 범위를 설명한다.

- 기존 `/agent3/impacts` 생성·조회·수정·review API를 재사용할 수 있다. 별도 서비스 백엔드의 미확정 API를 이번 UI를 위해 발명하지 않는다.
- 현재 Agent 3 흐름은 **영향 산정 → PM 확인/수정/승인 → 내부 협의안**이며, 승인 전 `draft=null`이다. 공수를 수정하면 재계산·새 결과·재승인으로 이어진다.
- 기존 Streamlit 화면은 API 대신 `Agent3Workflow`를 직접 실행한다. 새 화면의 API 연동과 동일한 실행 방식으로 보고하지 않는다.
- PRD M-20은 단가·금액 편집까지 넓게 제안하지만 현재 Agent 3 기본 API는 작업/MD/가정 편집 중심이다. 현 계약에 없는 직접 금액·일정 편집을 자동 구현하지 않는다.
- PRD·노션의 내부 승인/실무 리드/상업 승인과 현재 로컬 PM 산정 승인 gate는 동일한 업무 승인으로 확정하지 않는다. UI 문구와 단계 범위에 이 차이를 남긴다.
- PRD의 일정 예시 숫자와 Figma의 샘플 수치를 API 정답으로 쓰지 않는다. `schedule.business_days=null`은 0일이 아니라 미산정과 사유로 표시한다.
- 현재 저장은 메모리이고 `reviewer_ref`는 실제 사용자 인증을 대체하지 않는다. 로컬 확인 화면을 CN DB 저장·운영 권한 검증 완료로 표현하지 않는다.

## 기획 담당에게 넘길 확인 사항

| 결정할 항목 | 선택에 필요한 이유 |
|---|---|
| 이번에 만들 화면: C02~C04 중심인지 C05/C06 초안까지 포함할지 | 전체 제품 PRD와 현재 개인 로컬 확인 목표가 다름 |
| 화면만 mock으로 먼저 확인할지, 기존 Agent 3 API를 함께 연결할지 | 눈으로 보는 단계와 실제 AI 서버 업무 흐름 검증을 구분해야 함 |
| A1/A2·CN 영역은 읽기/fixture로 둘지 | 다른 담당자 구현·공유 계약을 이번 화면 작업으로 변경하지 않기 위해 |
| 실제 구현할 PM 확인·산정 대상 선택·승인 버튼의 범위 | Figma와 현재 Agent 3 승인 개념/입력 계약을 연결해야 함 |
| 로딩·빈 상태·실패·미입력·버전 충돌 수용 기준 | 정상 화면 설계만으로 실패·복구 동작을 확인할 수 없음 |

추가로 사용할 최종 PRD가 있다면 사용자에게 링크를 받을 수 있다. 현재 확인한 자료만으로도 이번 로컬 UI의 범위와 수용 기준 제안은 시작할 수 있으므로, PRD 링크를 다시 받기 전까지 모든 기획을 멈출 필요는 없다.
