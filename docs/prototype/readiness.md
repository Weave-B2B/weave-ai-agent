# 변경요청 확인용 UI — 기획 준비도

확인일: 2026-10-28 / Asia/Seoul. 작성: 개인 `dev-team-planner` 역할.
상태: **기획 검토 완료. 사용자가 혼합안(B) 화면 구현 착수를 승인했다.**

사용자 직접 답변: **“추천안으로 화면 구현 시작”**. C02~C04는 조회용 fixture,
C05의 산정·공수 수정·PM 승인/반려와 C06 내부 초안은 기존 Agent 3 API로 연결한다.
실제 외부 LLM 추론과 별도 QA 담당 착수는 이 답변으로 승인된 것으로 간주하지 않는다.

## 이번 요청

AI 서버 저장소에서 Figma의 변경요청 메뉴처럼 Agent 동작을 눈으로 확인할 수 있는 로컬 화면을 만든다.
기획·설계 자료가 부족하면 노션 또는 사용자에게 확인하고 필요한 문서를 `docs`에 정리한다.
담당자별 착수와 단계별 구현 수준은 사용자 답변을 받아 정한다.

이번 프로젝트의 서비스 백엔드·DB·인프라는 별도 담당이다. 기존 계약을 소비하는 화면과
최소 연결이 대상이며, 새 업무 백엔드·DB·사용자 인증·전체 메뉴·고객 발송/청구는 포함하지 않는다.
이 경계는 이번 프로젝트의 범위이며 개인 개발팀 전체의 역할 제한이 아니다.

원문 상태와 세부 근거는 [자료 출처 지도](source-map.md)를 기준으로 한다.

PRD/요구사항이 초안인 사실만으로 모든 개발을 막지는 않되, 업무 정책의 미결 사항을 UI가 임의 확정하지 않는다.

## 현재 API와 Figma의 차이

기존 코드 근거: `app/api/agent3_routes.py`, `app/agents/agent3/workflow.py`, `schema/schemas.py`.
기능 목록 형태의 노션 API 명세는 실제 `/agent3` HTTP 계약을 대체하지 않는다.

- 현재 전용 API는 산정 생성·조회·수정·승인/반려 네 개다. 공통 `/cases`의 전체 A1→A2→A3
  LLM 연결 및 새 승인 게이트 통합이 완료됐다고 간주하지 않는다.
- 산정 결과 `impact.estimates[].lines`에는 작업·항목·직군·MD·가정이 있다.
  `totals`에는 합계 MD·직군별 MD·원가·판매 산정가·마진이 있다.
  Figma의 **직군 단가·행별 금액**을 응답이 제공하는 것처럼 채우지 않는다.
  미제공 열은 표시를 생략하거나 `API 미제공`으로 설명하는 안이 필요하다.
- AI MD와 수정 MD를 나란히 보이려면 수정 전 결과와 최신 결과의 비교가 필요하다.
  다른 세션의 샘플 값을 실제 산정 이력으로 섞지 않는다.
- `schedule.business_days=null`은 **미산정**이다. 0일·고정 일수로 대체하지 않는다.
- Figma의 리드/상업 승인과 현재 API의 PM 영향 산정 승인은 같은 단계로 단정하지 않는다.
  개발 담당자 착수 승인도 제품의 PM 승인과 별개다.
- C04의 실제 산정 대상은 `pm_review.items[].estimate=true`다. 범위 밖 항목이라는 이유만으로
  자동 선택하지 않는다. 조회용 상위 단계에서는 합성 입력의 선택 근거를 표시한다.
- 질문 답변·요청 등록·고객 발송·상업 승인 등을 저장하는 새 API는 이번 작업에서 만들지 않는다.

## 유지해야 할 상태와 승인 규칙

| 실제 응답/상황 | 화면에서 보장할 것 |
|---|---|
| `WAITING_IMPACT_APPROVAL` | 산정은 표시하되 승인 전 협의안을 확정 초안으로 보여주지 않음 |
| `WAITING_INPUT` | 부족한 정보/질문을 표시하고 승인 가능으로 꾸미지 않음 |
| `WAITING_UPSTREAM_REVIEW` | 상위 PM 검토 필요를 표시. 실제 승인 데이터를 자동 생성하지 않음 |
| `NOT_REQUIRED` | 산정 대상 없음과 다음 조치를 설명. 빈 표/0원 정상 견적으로 바꾸지 않음 |
| `FAILED` | 실패 이유와 재시도 가능 범위를 표시 |
| `DRAFT_READY` | 현재 승인 결과의 내부 초안만 표시. 고객 승인·발송 완료로 바꾸지 않음 |
| 공수 수정 | 새 결과/버전·재계산 결과를 반영하고 기존 초안·승인을 현재 유효 결과에서 제거 |
| 일정 미산정 승인 | 사유를 보여주고 `acknowledge_unknown_schedule` 확인 후 요청 |
| HTTP 409 | 오래된 결과/단가 변경 등의 충돌을 알리고 최신 상태 확인 또는 새 산정을 유도. 자동 승인 재전송 금지 |
| HTTP 404 | 세션 없음/서버 재시작 등 현재 결과를 찾지 못함을 알림. DB 복구된 것처럼 표시하지 않음 |
| HTTP 422/502/503·통신 실패 | 입력·모델/상위 실패·데이터 가용성·연결 실패를 성공과 구분 |

현재 API는 신뢰된 로컬/백엔드 연동용이며 인증·인가를 구현한 공개 서비스가 아니다.
`reviewer_ref` 문자열은 실제 PM 신원 인증을 뜻하지 않는다. 프로세스 메모리 저장이라는 한계도 유지한다.

## 선택 확정과 남은 확인

1. [구현 계획](implementation-plan.md)의 **B 혼합안**을 사용자가 선택했고 화면 구현 시작을 승인했다.
2. C02~C04의 상위 결과는 샘플 조회, C06은 내부 초안 확인 범위다. 새 업무 API·DB·인프라를 만들지 않는다.
3. 초기 API 확인은 현재 가상 응답 설정을 기준으로 하며, 실제 외부 LLM 추론은 미승인이다.
   가상 응답을 실제 모델 품질 검증으로 보고하지 않는다.
4. 화면 담당은 승인된 목표 안의 작은 구현 선택을 진행할 수 있다. 새로운 업무 기능·실제 모델 호출·QA 담당 착수는
   매니저가 해당 범위를 사용자와 확인한다.

이번 문서는 위 선택과 현재 계약을 화면 담당에게 전달한다. 제품의 PM 승인 데이터를 사용자의 개발 착수 승인으로 만들지 않는다.

## 이번 검토에서 하지 않은 것

코드·API·공유 스키마·기존 데이터 딕셔너리·DB·인프라를 변경하지 않았다.
테스트·브라우저·API/외부 모델을 실행하지 않았다. 기존 테스트 통과 기록을 이번 UI의 검증 결과로 사용하지 않았다.
