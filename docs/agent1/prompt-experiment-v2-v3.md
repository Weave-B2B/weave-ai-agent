# Agent1 프롬프트 v2·v3 비교 실험 (#75)

- 일시: 2026-11-24 · 모델: OpenAI `gpt-6-luna` · 버전별 3회
- 입력: 상품 검색 필터 유지 확인 + 영문 상세페이지 검토 + 번역 주체·적용 범위 미정 + 11/23 오픈 일정 + 회신 형식 요청이 섞인 메일
- subject: `상품 검색 기능 및 영문 상세페이지 추가 검토 요청`

## 원인

1. **코드 후처리 덮어쓰기 (v2·v3 공통)**: `assemble.normalize_confirmation_items`가 인용에 "확인 부탁"이 있으면 text를 `{인용} 적용 가능 여부 확인`으로 바꿔 v3 형식이 깨짐.
2. **같은 대상 분할**: v3 5-1 예시가 기한과 "일정 영향 없이 희망"을 별도 항목으로 보여 줘 일정이 2~3개로 쪼개짐.
3. **15번 과적용**: "일정 조정 필요한지", "구현 방식 알려 달라" 같은 회신 요청까지 확인 항목이 됨.
4. **유지 요청 유형 흔들림**: 기존 협의 기능 "유지" 요청이 change_request로도 분류됨.

## 조치

- 코드: LLM이 이미 확인 항목으로 낸 text는 유지하고, function → confirmation으로 바꿀 때도 text를 덮어쓰지 않는다.
- v3 프롬프트
  - 같은 대상의 기준·희망·확인 요청은 한 항목으로 합친다(예시 교체).
  - 15번은 범위 판단·산정 규모가 바뀌는 쟁점만. 우리에게 답을 구하는 회신 요청은 관련 항목 또는 회신 형식 constraint에 합친다.
  - 기존 협의·계획 기능의 "유지" 요청은 confirmation.
  - 회신 형식 constraint는 하나로 합친다.

목표: 항목 5개(검색 필터 유지 확인 / 영문 상세 / 번역 주체 확인 / 오픈 일정 / 회신 형식) + 고객 질문 1개(적용 상품 수·범위).
