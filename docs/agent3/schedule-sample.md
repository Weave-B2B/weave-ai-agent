# 일정 계산 확장용 샘플

2026-11-18 작성. `data/scenarios/schedule-v1-sample.json`은 **합성 입력과 손으로 배정한 기대값**이다.
실제 고객 데이터·공휴일·현재 운영 일정 계산기의 결과로 사용하지 않는다.

| 항목 | 입력 |
|---|---|
| 기준일 / 계획 착수일 | 2026-11-22 / 2026-11-23 |
| 기존 작업 | FE 8h, BE 8h, QA 8h |
| 일별 유효 투입 시간 | FE 4h, BE 8h, QA 4h (기존 업무 제외 후) |
| 선행 관계 | FE·BE 후 QA. 변경 시 BE 후 리뷰 API, FE·리뷰 API 후 QA |
| 회사 휴무일 | 11/27 (가상 회사의 예시 휴무) |
| 변경 작업 | 리뷰 API 16h 추가, QA 4h 증가 |
| 공수 증감 | 20h = 2.5 MD (1 MD = 8h) |

## 손으로 배정한 기대값

| 작업 | 기존 | 변경 후 |
|---|---|---|
| FE | 11/23~24 | 동일 |
| BE | 11/23 | 동일 |
| 리뷰 API | 없음 | 11/24~25 |
| QA | 11/25~26 | 11/26, 11/30, 12/1 |
| 완료일 | 11/26 | 12/1 |

일정 영향은 11/26 이후 12/1까지의 영업일(11/30, 12/1) **2일**이다.
추가 공수 2.5 MD와 프로젝트 지연 2영업일은 다른 값이다.
의존성은 선행 작업 종료 후 **다음 영업일 착수**를 가정한다. 당일 이어받기·분할 병렬화는 적용하지 않는다.

`tests/test_schedule_sample.py`는 입력과 기대 배정의 작업량 합계·휴일·선행 조건·가용시간을 검증한다.
이 검증은 운영 스케줄러의 구현 완료를 의미하지 않는다. 다음 단계에서 이 입력을 받아 실제로 배정하고
동일 기대값을 반환하는 계산기를 구현한 후, 문서 업로드·Jira 등 데이터 수집 경로를 붙인다.
