# 일정·공수 엑셀 업로드와 Agent 3 연결

작성일: 2026-11-19. 로컬 구현. 고급 일정 계산기 연결은 후속 작업이다.

## 사용자 흐름

1. 프로젝트 상세 → 문서 기준 → 문서 추가에서 XLSX를 선택한다.
2. 문서 유형 **일정·공수 자료**(`IMPACT_WORKBOOK`)로 등록한다. XLSX는 이 유형으로 자동 분류되며 PDF 계약 문서로 등록할 수 없다.
3. **영향 산정 자료 사용 승인**과 적용일을 지정한다. 미승인 자료는 저장만 한다.
4. 같은 화면의 **영향 산정 자료** 목록에서 확인한다. 계약 기준선 문서 목록과는 별도다.
5. Agent 3 실제 실행 시 승인되고 적용일이 지난 가장 최근 자료 한 개를 직접 읽는다.

형식은 `.xlsx`, 최대 10MB다. `STORED`는 원본 업로드 완료를 뜻하며, 엑셀 내용 검증·일정 계산 완료를 뜻하지 않는다. 내용 오류는 Agent 3가 읽을 때 표시한다.

## 분리 원칙

- 업로드 저장소(S3)는 기존 파일 업로드를 그대로 사용한다. 파일 용도는 `IMPACT_WORKBOOK`이다.
- 문서 버전의 처리 상태는 `STORED`. 색인 이벤트·텍스트 청킹·임베딩·벡터 저장을 실행하지 않는다.
- 계약 기준선에 BASELINE/REFERENCE 어느 역할로도 추가할 수 없다. 계약 근거 수동 청크 등록, 색인 결과 콜백·재시도도 차단한다.
- AI 색인 API도 문서 유형 또는 XLSX MIME으로 잘못 전송된 요청을 임베더 생성 전에 거절한다.
- Agent 2에는 전달하지 않는다. Agent 3 입력의 `operational_schedule`로만 전달하며 계약 범위 근거로 인용하지 않는다.
- 엑셀의 **단가표는 조회용**이다. 공식 단가·원가·금액은 백엔드 등록 단가표와 계산 API를 사용한다. 이 시트의 가격을 모델에 보내지 않는다.

## 구조화 양식

| 시트 | 입력 항목 | 처리 |
| --- | --- | --- |
| 기존 작업 | 일정 계산 시작일, 현재 계획 완료일(선택), 작업명·담당자·남은 시간(h)·선행 작업명 | 기존 작업은 신규 요청의 추가 공수에 합산하지 않음 |
| 사람과 근무일 | 근무요일, 담당자·하루 투입 가능시간(h)·투입 가능일(선택), 예외 근무일 | 시작일 생략은 프로젝트 계산 시작일 사용. 하루 0~24시간 |
| 단가표 | 등록 단가 조회용 | 공식 계산 입력으로 사용하지 않음 |

선행 작업은 작업명을 세미콜론으로 구분한다. 중복 작업명·담당자, 알 수 없는 담당자/선행 작업, 순환 선행관계, 음수/누락 공수, 외부 연결·매크로·입력 수식은 거절한다. 요약 합계 수식은 실행하지 않는다. 작업·인력은 각각 200행, 예외 근무일은 1000행까지 지원한다.

지원하는 것은 공유한 간소화 양식이다. 임의의 WBS 엑셀을 자동 추론해 받아들이지는 않는다. 계획 완료일이 없으면 지연 폭을 미산정으로 남긴다. 휴무 빈칸도 실제 휴무 없음 확정을 뜻하지 않는다.

## 연결 계약

- Backend: `GET /internal/v1/projects/{projectId}/impact-workbook`
- 인증: 기존 `X-Internal-Token`. 새 시크릿 불필요.
- 반환: `{ "workbook": null }` 또는 원본 정보(projectId, documentId, documentVersionId, version, title, objectKey, sha256, mimeType, sizeBytes).
- 선택: `IMPACT_WORKBOOK + APPROVED + STORED + 적용일 <= 오늘(미입력은 즉시)` 중 등록 시점 최신 1개. 새 버전이 미승인/미래 적용이면 이전 유효 승인 버전을 계속 사용한다.
- AI는 지정된 `S3_SOURCE_BUCKET`에서 objectKey 원본을 크기 제한 내 읽고, 파일 크기·SHA-256을 확인한다. Backend S3 버킷과 같은 저장소를 가리켜야 한다.
- 자료 없음은 기존 분석 흐름을 유지한다. 조회/저장소 장애는 자료 없음으로 숨기지 않고 실패로 표시한다. 합성 프로젝트는 조회하지 않는다.
- `impact_workbook.source`에 버전·해시, `data`에 구조화 입력을 결과에 고정한다. Run payload에서도 보존한다.
- 사용 자료 교체·승인 철회·적용일 변경으로 현재 원본이 달라지면 AI 검토·문서 생성과 Backend 최종 산정 대조에서 재산정을 요구한다. 기존 문서·승인을 그대로 재사용하지 않는다.

## 적용과 검증 범위

Backend 수동 마이그레이션 `src/main/resources/db/manual/V20261119__a_impact_workbook.sql`은 문서 유형·파일 용도·처리 상태의 DB CHECK 허용값을 확장한다. 로컬 DB에 적용했다. 배포 DB는 Backend 배포 전에 별도로 적용해야 한다.

Frontend·Backend·AI를 함께 재시작해야 새 유형과 내부 조회 경로가 반영된다. 새 환경변수나 Jira 연결은 필요 없다. 실제 UUID 프로젝트는 Backend 조회 경로가 준비되어 있어야 한다.
